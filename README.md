# Chrome 프로필 북마크 실시간 동기화

이 PC의 모든 Chrome 프로필이 같은 북마크를 쓰게 한다. 어느 프로필에서 북마크를 추가·수정·이동·삭제·정렬하든 열려 있는 다른 프로필에 즉시 반영되고, 닫혀 있던 프로필은 열리는 순간 따라잡는다.

```
[프로필 확장] [프로필 확장] … ── WebSocket(127.0.0.1:47321) ── [로컬 허브(Node.js)]
                                                                 └ hub/data/state.json  기준 트리
```

- **확장(extension/)**: 각 프로필에 같은 확장을 설치한다. `chrome.bookmarks` 이벤트를 허브로 보내고, 허브가 보낸 변경을 적용한다. `manifest.json`의 `key`로 확장 ID를 `cchkhligdoboaipldlkkjjdfpmieomcd`로 고정해, 허브는 이 ID에서 온 연결만 받는다.
- **허브(hub/)**: 기준 트리를 들고 변경을 검증·적용한 뒤 다른 프로필에 전달한다. 처음에는 `config.json`의 `masterEmail` 프로필의 북마크로 기준 트리를 만들고, 다른 프로필은 그 트리로 덮어쓴다.
- **어긋남 복구**: 각 확장이 5분마다 자기 트리 해시를 허브와 비교한다. 다르면 허브 기준으로 다시 맞춘다.
- **대량 삭제 보호**: 이미 맞춘 프로필에 허브가 북마크를 30% 넘게(20개 이상) 지우라고 하면 적용을 멈춘다. 확장 아이콘에 빨간 `!`가 뜨고, 팝업에서 확인해야 적용된다.

## 설치

1. **백업**: `npm run backup`을 실행한다. 모든 프로필의 `Bookmarks` 파일이 `backups/<시각>/`에 복사된다.
2. **설정**: `hub/config.example.json`을 `hub/config.json`으로 복사하고, `masterEmail`에 기준이 될 프로필의 Google 계정 주소를 적는다. `config.json`은 git에 올라가지 않는다.
3. **허브 실행**: `npm install`을 한 뒤 둘 중 하나로 띄운다.
   - 자동 시작: PowerShell에서 `scripts\install-autostart.ps1`을 실행한다. 로그온할 때 창 없이 뜬다.
   - 직접 실행: `npm run hub`
   - 상태 확인: <http://127.0.0.1:47321/status>
4. **확장 설치**: 메인 프로필(`masterEmail` 계정)에 **먼저** 설치하고, 이어서 나머지 프로필에 설치한다.
   - `chrome://extensions` → 오른쪽 위 「개발자 모드」 켜기 → 「압축해제된 확장 프로그램 로드」 → `extension` 폴더를 선택한다.
   - 메인 프로필에 설치하면 허브가 그 북마크로 기준 트리를 만든다. 다른 프로필은 설치하는 즉시 기준 트리로 덮어써진다.
   - 아이콘 배지: 없음 = 맞춰짐, `…` = 맞추는 중이거나 메인을 기다리는 중, `OFF` = 허브 연결 끊김, `!` = 확인 필요, `?` = 허브 기준으로 맞춰도 같은 차이가 계속 남음(허브 로그 `check stuck` 확인).

## 알아둘 점

- 프로필 창이 닫혀 있으면 확장이 돌지 않는다. 그 프로필은 다음에 열 때 맞춰진다.
- 각 프로필이 자기 Google 계정과 북마크 동기화 중이면, 바뀐 북마크가 그 계정(다른 기기 포함)에도 올라간다. 덮어쓰기도 마찬가지다.
- 동시에 같은 북마크를 고치면 허브에 먼저 도착한 쪽이 기준이 되고, 늦은 쪽은 허브 기준으로 맞춰진다.
- Chrome 157은 비어 있는 「모바일 북마크」 폴더를 확장에 보여 주지 않는다. 그런 프로필에는 모바일 북마크가 전파되지 않으므로 모바일 폴더는 쓰지 않는다.
- 5분 점검에서 허브 기준으로 맞춘 뒤에도 같은 차이가 5번 넘게 이어지면, 허브가 그 프로필에 다시 맞춤을 그만 보내고 `check stuck`을 남긴다.

## 복원

1. 모든 프로필에서 이 확장을 끈다. 켜 두면 허브가 다시 덮어쓴다.
2. 복원할 프로필 창을 모두 닫는다.
3. `backups/<시각>/<프로필 폴더>/Bookmarks`를 `%LOCALAPPDATA%\Google\Chrome\User Data\<프로필 폴더>\Bookmarks`로 복사한다.

허브의 기준 트리도 `hub/data/backups/state-YYYY-MM-DD.json`에 날마다 한 벌씩 30일치가 남는다. 되돌리려면 허브를 멈추고 이 파일을 `hub/data/state.json`으로 복사한 뒤 다시 띄운다. 그다음 각 프로필 팝업에서 「허브 기준으로 적용」을 누른다.

## 제거

- 자동 시작 해제: `Unregister-ScheduledTask -TaskName ChromeBookmarkSyncHub -Confirm:$false`
- 각 프로필의 `chrome://extensions`에서 확장을 삭제한다.

## 확장 코드를 고친 뒤

Chrome은 디스크의 확장 코드가 바뀌어도, 새로고침하기 전까지 옛 코드를 계속 돌린다. 프로필 창을 닫았다 열어도 마찬가지다. 그래서 고친 뒤에는 반드시 다시 읽게 한다.

1. `manifest.json`의 `version`을 올린다. 메시지 규약이 바뀌었으면 `shared.js`의 `PROTOCOL`도 올린다.
2. 허브에 연결된 프로필의 확장을 다시 읽게 한다.

   ```
   curl -X POST -H "X-BmSync: 1" http://127.0.0.1:47321/reload-extensions
   ```

3. 닫혀 있던 프로필은 열어서 `chrome://extensions`의 이 확장 「새로고침」을 누른다.
4. <http://127.0.0.1:47321/status>에서 모든 프로필의 `version`이 새 값인지 확인한다. 허브 로그에 `old extension code in …`이 보이면 그 프로필은 아직 옛 코드다. 1.0.0에는 다시 읽기 처리가 없어서 2번이 듣지 않는다.

## 개발

- `npm test`: 가짜 `chrome.bookmarks`(Chrome의 이동 위치 규칙과 이벤트 순서를 흉내 냄)로 허브와 여러 프로필을 연결해 시뮬레이션한다.
- `extension/shared.js`는 허브도 가져다 쓴다. 직렬화 형식은 이 파일 한 곳에서만 고친다.
